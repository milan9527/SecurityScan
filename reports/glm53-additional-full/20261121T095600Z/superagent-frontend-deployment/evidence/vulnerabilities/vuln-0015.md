# Path traversal in pack-deploy onboarding/deploy via unvalidated packId and scopeDirName

**ID:** vuln-0015
**Severity:** MEDIUM
**Found:** 2026-11-21 10:03:37 UTC
**Target:** /workspace/agentcore-superagent-update/super-agent (backend)
**CWE:** CWE-22
**CVSS:** 4.3
**Confidence:** High
**Fix Effort:** Low

## Description

The pack onboarding and deploy endpoints pass the raw packId and scopeDirName path parameters into Node path.join() with no validation or containment check, so URL-encoded traversal sequences let an authenticated user read JSON files outside the industry-packs directory tree.

## Evidence

Local unit PoC `backend/tests/unit/pack-deploy-traversal.poc.test.ts`: a marker `onboarding.json` containing `TRAVERSAL-MARKER-9f31ab` is written to a temp directory outside the packs root; the packs base dir is pointed there; GET /api/packs/onboarding/<packId>/%2e%2e%2f%2e%2e%2fleaked-scope returns the marker content, proving the traversal escapes the industry-packs/scopes subtree.

## Impact

Authenticated arbitrary-file read (JSON files only, via the onboarding reader) relative to the process working directory: can disclose configuration files, deployment metadata, or other packs' content present on the server filesystem as JSON. Limited to files that parse as JSON on this path; no write or execute primitive demonstrated.

## Counterevidence

Checked for guards: (1) the route validates only that packId and scopeDirName are present strings (pack-deploy.routes.ts:64-70) — no character or format validation; (2) the service performs no path normalization, prefix check, or containment assertion before existsSync/readFile; (3) no authorization check ties the operation to a pack catalog. The Fastify router URL-decodes path params, which is what makes URL-encoded ../ effective and is a fact to state, not a control. Fastify's default 404 behavior does not restrict param characters. No control found. Mitigating: the read is constrained to a JSON parse — non-JSON files throw and return null, so disclosure is limited to parseable onboarding.json content (or, on the deploy path, whatever JSON/YAML the deploy routine reads).

## Confidence Rationale

Complete source trace: unvalidated path params flow into join() with no normalization or containment check at any of the cited lines, and the local unit PoC (pack-deploy-traversal.poc.test.ts) reads a marker onboarding.json placed in a temp directory outside the packs root via URL-encoded traversal in scopeDirName. Live-server behavior not tested.

## What Would Change This Severity

Demonstrated disclosure of a secret-bearing JSON file on the server (e.g. a config with credentials) would raise severity; confirmation that the industry-packs root and all readable JSON are non-sensitive would lower it to low.

## Technical Analysis

`routes/pack-deploy.routes.ts:38` (`GET /onboarding/:packId/:scopeDirName`) and the POST /deploy handler (line ~38-80) pass the raw params to `packDeployService`. In `services/pack-deploy.service.ts`, `getOnboardingConfig` (line 118) builds `packDir = join(baseDir, 'industry-pack-' + packId)` and `scopeDir = join(packDir, 'scopes', scopeDirName)` / `twinDir = join(packDir, 'digital-twins', scopeDirName)` (lines 120-126) with no sanitization, then `readFile(join(resolvedDir, 'onboarding.json'))` (line 131). Node's `join` does not neutralize `../` segments, and Fastify URL-decodes path params, so a URL-encoded `..%2f` (or literal ../) in scopeDirName or packId walks out of the industry-packs tree. The deploy path (`deployScope`, lines 226-235) uses the same unvalidated joins when reading scope.json/twin.json/manifest/workflow files.

## Proof of Concept

1. Authenticate with any account. 2. Send GET /api/packs/onboarding/customer-service/%2e%2e%2f%2e%2e%2f%2e%2e%2fetc-adjacent-target — the router decodes %2e%2e%2f into ../, and path.join resolves outside the pack directory. 3. If the resolved directory contains onboarding.json, its content is returned to the caller. 4. The deploy endpoint POST /api/packs/deploy with the same traversal in scopeDirName reaches the analogous joins in deployScope (:226-235).

```ecl
# Unit PoC: cd super-agent/backend && npx vitest run tests/unit/pack-deploy-traversal.poc.test.ts
# Marker onboarding.json OUTSIDE the packs tree is returned via traversal:
GET /api/packs/onboarding/<packId>/%2e%2e%2f%2e%2e%2fleaked-scope
-> 200 { data: { secret: "TRAVERSAL-MARKER-9f31ab" } }
# (Fastify decodes %2e%2e%2f -> ../, join(baseDir, 'industry-pack-<packId>',
#  'scopes', '../../../leaked-scope') escapes the subtree)
```

## Remediation

Validate packId and scopeDirName against a strict format (e.g. ^[a-z0-9-]+$) before any filesystem use, and after constructing each path, verify containment by resolving it and checking that the resolved path remains inside the packs base directory (resolve() + startsWith(baseDir) with a trailing separator), rejecting otherwise. Apply the check in both getOnboardingConfig and deployScope in pack-deploy.service.ts.

## Assumptions

Authenticated user with access to the pack routes (any role). Exploit requires readability of a target file as `onboarding.json` (or, for the deploy variant, valid pack structure) outside the industry-packs tree. Production exposure and industry-packs directory contents unverified.
