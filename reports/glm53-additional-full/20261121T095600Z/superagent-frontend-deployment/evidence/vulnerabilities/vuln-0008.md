## Description

The frontend pins `xlsx` (SheetJS) 0.18.5 in `frontend/package.json`, which is affected by CVE-2023-30533 (prototype pollution via crafted worksheet, fixed in 0.19.3). The library parses attacker-supplied spreadsheet files in the chat file preview.

## Evidence

**Advisory evidence:** `CVE-2023-30533` applies to `xlsx` at installed version `0.18.5`. The advisory is fixed in `0.19.3`.

**Dependency chain:** `xlsx@0.18.5`

**Usage analysis:** the package is loaded, but this advisory's vulnerable code does not run here. Import site: `frontend/src/pages/Chat.tsx:179` (`const XLSX = await import('xlsx')`). Call sites: `XLSX.read(arrayBuffer, { type: 'array' })` (Chat.tsx:181) and `XLSX.utils.sheet_to_json<string[]>(workbook.Sheets[name]!, { header: 1 })` (Chat.tsx:184). The advisory's pollution vector requires sheet keys like `__proto__`/`constructor.prototype` to be merged into a target object (object output of sheet_to_json / prototype-key handling); this code path uses `{header: 1}` producing arrays of arrays, and cells are rendered as `String(cell)` inside React text nodes (Chat.tsx:349), so no prototype-key merge or raw HTML sink is reached. Chain: chat file preview entry point -> Chat.tsx:179 import -> Chat.tsx:184 array-mode conversion -> escaped React rendering.

## Impact

A crafted .xlsx opened in the chat workspace viewer pollutes `Object.prototype` in the victim's browser tab. The same tab holds the auth token in localStorage, so a pollution-driven gadget in the SPA could be leveraged toward script execution and token theft; at minimum it corrupts application state and can crash the tab.

## Confidence Rationale

Static source-to-sink trace is complete and the entry path (workspace file preview) is core product functionality; the parse runs on every spreadsheet preview. No dynamic PoC was run per the local-only assessment constraints.

## What Would Change This Severity

Identification of a concrete prototype-pollution gadget in the frontend bundle (e.g. a merge/extend over object keys reachable post-parse) would raise this to high; confirmation that workspace spreadsheets can never originate from agent output would lower it.

## Contextual CVSS

The file content is agent-generated output, not a trusted asset, so the source is attacker-influenceable (a compromised or prompt-injected agent produces the crafted .xlsx) — prerequisites L, user_interaction R, complexity H (requires the agent to emit the malicious file and the victim to open it). Impact in this context is prototype pollution of the victim's browser tab (integrity L, availability L); the same tab holds the auth token in localStorage (Chat.tsx:159), so scope crosses into the browser-origin authority (C). ## Remediation

Upgrade SheetJS to a fixed release (0.19.3 or later via the SheetJS CDN, as the npm `xlsx` package is frozen at 0.18.5), or switch to the maintained `xlsx` distribution source; alternatively replace with another spreadsheet parser. Additionally, validate that any future use of sheet_to_json does not switch to object output (`header` omitted) on untrusted files.

## Assumptions

Static code-trace only; no dynamic reproduction performed (local-only assessment, no running app with a crafted workbook). Advisory data taken from the local trivy vulnerability DB; production bundle may differ if the dependency has since been upgraded.
