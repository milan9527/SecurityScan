# Unauthenticated WebSocket subscription to arbitrary execution events at /ws/executions

**ID:** vuln-0026
**Severity:** MEDIUM
**Found:** 2026-11-21 10:07:02 UTC
**Target:** super-agent backend (local repository /workspace/agentcore-superagent-update)
**CWE:** CWE-306
**CVSS:** 6.5
**Confidence:** High
**Fix Effort:** Low

## Description

The /ws/executions WebSocket endpoint registers with no authentication preHandler and performs no ownership or tenant check on subscription. Any unauthenticated client that can reach the API can subscribe to arbitrary workflow executions and receive execution events, breaking tenant isolation of execution streams.

## Evidence

Local runtime PoC against the real gateway module (S3/DB mocked): an unauthenticated ws client connected to /ws/executions, sent {"type":"subscribe","executionId":"<arbitrary-uuid>"}, and received {"type":"subscribed"} confirming the subscription to another tenant's execution stream.

## Impact

Unauthenticated cross-tenant subscription to execution event streams. The subscription to an arbitrary executionId was confirmed; events may carry node outputs, errors, and intermediate results (verified only as subscription success and event routing — the sensitivity of the data carried in event payloads in production was not exhaustively enumerated). Potential availability impact from unauthenticated connection flooding. No integrity impact demonstrated.

## Counterevidence

Checked the route registration (no preHandler array, unlike HTTP routes which use [authenticate, requireModifyAccess, ...]) and the full handleSubscribe path — no tenant/ownership verification exists anywhere between connection and subscription confirmation. The 'subscribed' confirmation and routing to broadcast were verified at runtime; what the event payload contains beyond the verified subscription flow was not exhaustively enumerated, and that uncertainty is reflected in a Medium confidentiality rating.

## What Would Change This Severity

Confirmation that execution event payloads include node outputs or other tenant-sensitive content in production would raise confidentiality and severity; evidence that the gateway is only bound to an authenticated internal network in deployment would lower it.

## Technical Analysis

In backend/src/websocket/execution.gateway.ts:135-141, the route `fastify.get('/ws/executions', { websocket: true }, handler)` is registered with no `preHandler` — unlike sibling HTTP routes which use `authenticate`. `handleConnection` accepts the socket without verifying the request's JWT or tenant. `handleSubscribe` (line 232) validates only that `executionId` is a non-empty string (lines 233-242); there is no lookup of the execution record, no ownership check, and no tenant comparison, after which the client is added to that execution's subscriber set. Because the execution ID space is UUIDs, guessing an active ID is low probability per attempt, but any leaked/reconnoitered executionId grants live event access, and the endpoint additionally allows unauthenticated connection resource consumption.

## Proof of Concept

1. With no credentials or session, open a WebSocket to ws(s)://<host>/ws/executions.
2. Send {"type":"subscribe","executionId":"<any UUID>"}.
3. Receive {"type":"subscribed"} — the client is now registered on that execution's broadcast list and receives all subsequent events for it.

```js
// Local PoC against the Fastify app with the gateway registered
import WebSocket from 'ws';

const ws = new WebSocket('ws://127.0.0.1:PORT/ws/executions'); // no auth headers/cookies
ws.on('open', () => {
  ws.send(JSON.stringify({ type: 'subscribe', executionId: '11111111-1111-1111-1111-111111111111' }));
});
ws.on('message', (m) => {
  console.log('received:', m.toString()); // -> {"type":"subscribed"} for an arbitrary executionId
});
```

## Remediation

Require authentication on the /ws/executions route (verify the Cognito JWT during the WebSocket handshake, e.g. via the preHandler or the verifyClient/upgrade path) and, in handleSubscribe, verify that the authenticated user's organization/tenant owns the requested executionId (load the execution record and compare tenant) before adding the client to the subscribers map.

## Assumptions

Assumes the WebSocket gateway is mounted on the public API in production (same registration path as HTTP routes). Production exposure and whether events carry sensitive node outputs at scale are unverified.
