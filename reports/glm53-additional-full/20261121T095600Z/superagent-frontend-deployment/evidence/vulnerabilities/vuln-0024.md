## Description

The backend pins `undici` 6.24.1 in `backend/package-lock.json` (transitive via `@anthropic-ai/claude-agent-sdk` and `discord.js`). undici versions 4.0.0–<6.29.1 are affected by CVE-2026-109383 (advisory CVSS 9.1): the Agent dispatcher deep-clones its constructor options via JSON before forwarding them to per-origin pools, silently dropping a caller-supplied `tls.checkServerIdentity` callback — so a TLS peer that a custom certificate check was written to reject is silently accepted if it passes Node's default checks.

## Evidence

**Advisory evidence:** `CVE-2026-109383` applies to `undici` at installed version `6.24.1`. The advisory is fixed in `6.29.1`.

**Usage analysis:** the package is loaded, but this advisory's vulnerable code does not run here. Import check: no application code imports undici (rg 'undici' over backend/src returns nothing). Resolution chains: @anthropic-ai/claude-agent-sdk@0.2.37 and discord.js@14.26.2 -> undici 6.24.1 (backend/package-lock.json:11639). Affected-symbol check: the advisory's vulnerable path requires a caller to construct an undici Agent/ProxyAgent with a tls option containing a checkServerIdentity callback; a complete search of backend/src for 'undici', 'ProxyAgent', 'checkServerIdentity', 'setGlobalDispatcher' found no callers. The library is loaded by its parent packages for their own outbound requests (Bedrock/Anthropic API calls, Discord gateway), but no application-supplied TLS customization flows into it, so the silently-dropped-callback behavior never executes on this codebase's paths.

## Impact

No application code creates undici Agents or supplies TLS options, so the dropped-callback path has no caller in this codebase; the finding documents the CVSS-9.1-vulnerable undici pinned in the production dependency tree, relevant only if a future code path configures custom TLS verification through undici.

## Remediation

Add an npm override in backend/package.json ("overrides": { "undici": "^6.29.1" }) so the claude-agent-sdk/discord.js chains resolve a patched undici, and verify with `npm ls undici`. No code change required today.
