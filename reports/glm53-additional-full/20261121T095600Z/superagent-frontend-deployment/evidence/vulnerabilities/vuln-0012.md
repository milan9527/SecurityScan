## Description

The frontend pins `xlsx` (SheetJS) 0.18.5, affected by CVE-2024-22363 — regular expression denial of service when parsing crafted spreadsheet content, fixed in 0.20.2. The library parses attacker-supplied Excel files in the chat preview.

## Evidence

**Advisory evidence:** `CVE-2024-22363` applies to `xlsx` at installed version `0.18.5`. The advisory is fixed in `0.20.2`.

**Dependency chain:** `xlsx@0.18.5`

**Usage analysis:** the advisory's vulnerable code runs in this codebase. Import and call site: `frontend/src/pages/Chat.tsx:179-184` — the file-preview flow does `await import('xlsx')` then `XLSX.read(arrayBuffer, { type: 'array' })` running the parser over attacker-controlled workbook bytes. The affected parsing code executes on this path; the CVE's ReDoS manifests as excessive CPU during read of a crafted file. Chain: chat workspace file open (entry point) -> Chat.tsx:179 dynamic import -> Chat.tsx:181 XLSX.read on untrusted arrayBuffer (package call).

## Impact

A crafted spreadsheet opened in the chat file preview can cause catastrophic regex backtracking during parsing, freezing the victim's browser tab (client-side denial of service). No confidentiality or integrity impact; no server-side resource consumption since parsing occurs in the browser.

## Contextual CVSS

Entry point: authenticated user opens an Excel workspace file in chat file preview -> `import('xlsx')` at frontend/src/pages/Chat.tsx:179 -> `XLSX.read(arrayBuffer, {type:'array'})` at Chat.tsx:181 on attacker-controlled bytes. The ReDoS path in SheetJS parsing executes here directly on untrusted input, so the vulnerable code runs; however the impact is a browser-tab hang for the single victim who opens the crafted file (PR:L because the file must be placed in the victim's session workspace, UI:R for opening the preview), so availability is L rather than H server-side and confidentiality/integrity are N.

## Remediation

Upgrade SheetJS to 0.20.2 or later (SheetJS CDN distribution; the public npm `xlsx` package is frozen at 0.18.5), or replace with a maintained spreadsheet parser that does not use vulnerable regexes on untrusted input.

## Assumptions

Static code-trace only; no dynamic reproduction (no running app with a crafted workbook). Advisory data from the local trivy vulnerability DB. ReDoS impact confined to the victim's browser tab.
