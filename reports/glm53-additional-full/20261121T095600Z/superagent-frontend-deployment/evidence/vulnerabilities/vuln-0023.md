## Description

The agentcore runtime pins `ip-address` 10.2.0 in `agentcore/package-lock.json` (transitive via `@anthropic-ai/claude-agent-sdk` -> `@modelcontextprotocol/sdk`). Prior to 10.3.1, `Address4` accepts octets with a leading zero and decodes them as decimal, while the network stack (WHATWG URL parser, inet_aton, getaddrinfo) decodes leading-zero octets as octal — the library and the network stack disagree about which host a string names (CVE-2026-69192, advisory CVSS 8.6). Applications that build trust-boundary decisions (e.g. private-IP / SSRF allowlist checks) on Address4.isPrivate() can be tricked into connecting to a different host than the one validated.

## Evidence

**Advisory evidence:** `CVE-2026-69192` applies to `ip-address` at installed version `10.2.0`. The advisory is fixed in `10.3.1`.

**Usage analysis:** the advisory does not apply here: the vulnerable package is not loaded, or the installed copy is not affected. Import check: no application code imports ip-address — a complete search of agentcore/src, backend/src and frontend/src for 'ip-address', 'Address4', 'Address6' finds no imports or symbol usage (the only matches are an unrelated ipAddress field in backend/src/services/webhook.service.ts:140, a plain string compared with Array.includes, not the library). Resolution chain: @anthropic-ai/claude-agent-sdk@0.2.141 -> @modelcontextprotocol/sdk@1.29.0 -> ip-address@10.2.0 (agentcore/package-lock.json:1994). Affected-symbol check: the advisory's vulnerable symbols (new Address4(...), correctForm(), isPrivate()) have no caller in application code, and the webhook allowedIps check at backend/src/services/webhook.service.ts:155 uses exact string matching against request.ip, not the library. Nothing the shipped code loads invokes the library's parsing on attacker-controlled input, so the advisory does not apply to this codebase beyond the pinned-version exposure.

## Impact

No application code in this repository uses the `ip-address` library, so the octal/decimal confusion has no reachable trust-boundary decision to subvert here. The finding documents the vulnerable pinned version in the agent runtime's dependency tree; it matters only if the SDK (or future code) performs IP-based filtering on attacker-controlled URLs using this library.
