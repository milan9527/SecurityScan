# react-router 7.12.0 in frontend (CVE-2026-42211 and related 2026 CVEs, not reachable in Declarative Mode)

**CVE:** CVE-2026-42211
**CWE:** CWE-502
**Advisory CVSS:** 7.5
**Contextual CVSS Vector:** CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:N/I:N/A:N
**Fix Effort:** Low

## Description

The frontend pins `react-router` 7.12.0 (via direct dependency `react-router-dom` ^7.12.0) in `frontend/package-lock.json`. react-router 7.0.0–7.14.1 is affected by CVE-2026-42211 (advisory CVSS 8.1): in Framework Mode, a multi-step attack leveraging a pre-existing prototype-pollution vulnerability can lead to unauthorized remote code execution. The same pinned version carries additional 2026 advisories (CVE-2026-34077 RSC redirect XSS, CVE-2026-42342 __manifest resource exhaustion) that are likewise confined to Framework/RSC usage.

## Evidence

**Advisory evidence:** `CVE-2026-42211` applies to `react-router` at installed version `7.12.0`. The advisory is fixed in `7.14.2`.

**Dependency chain:** `react-router-dom@7.12.0 > react-router@7.12.0`

**Usage analysis:** the package is loaded, but this advisory's vulnerable code does not run here. Import check: frontend/src/App.tsx:1 imports BrowserRouter, Routes, Route, Navigate from 'react-router-dom' (direct dependency ^7.12.0), resolving to react-router 7.12.0 (frontend/package-lock.json:6275). Affected-symbol check per advisory: CVE-2026-42211 requires Framework Mode (server-side request handling with route modules / external requests); the advisory states it does not impact Declarative Mode (<BrowserRouter>) or Data Mode. The application mounts the router exclusively in Declarative Mode at frontend/src/App.tsx:80 (<BrowserRouter>), has no createBrowserRouter/RouterProvider usage (complete search of frontend/src), no RSC/unstable API usage (CVE-2026-34077's precondition), and no server-side rendering that could expose the __manifest endpoint (CVE-2026-42342). Chain: SPA bootstrap -> App.tsx:80 BrowserRouter (only usage) -> react-router 7.12.0 Declarative Mode client rendering — the vulnerable server-side code paths never execute.

## Impact

This application uses Declarative Mode (`<BrowserRouter>`), which all three advisories explicitly exclude from impact, so no exploitable path exists as the app is written. The finding documents the vulnerable pinned version; impact would only materialize if the app migrated to Framework Mode / RSC APIs without upgrading.

## Contextual CVSS

react-router 7.12.0 is loaded and executed on every page (frontend/src/App.tsx:80 wraps the SPA in BrowserRouter), but the application uses Declarative Mode only — confirmed by the router wiring at frontend/src/App.tsx:1 and :80 (no createBrowserRouter/RouterProvider anywhere in frontend/src). The advisory's affected surface (Framework Mode server-side rendering plus a pre-existing prototype-pollution gadget) does not run in this codebase: there is no react-router server runtime and no SSR, so the RCE path cannot execute under any attacker input here. All impact metrics are N as used; the report documents the vulnerable pinned version for upgrade hygiene.

## Remediation

Bump react-router-dom to a release containing the fixes (>= 7.15.0 covers all three advisories; >= 7.14.2 covers CVE-2026-42211) in frontend/package.json and regenerate the lockfile. No code change is required; the Declarative Mode usage is unaffected.
