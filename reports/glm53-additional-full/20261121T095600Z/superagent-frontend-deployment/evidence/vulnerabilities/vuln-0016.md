# CVE-2026-48779 in ws 8.19.0 (WebSocket small-fragment memory exhaustion DoS of the chat gateway)

**ID:** vuln-0016
**Severity:** HIGH

**Target:** super-agent (backend)
**Package:** ws
**Ecosystem:** npm

**Dependency Chain:** @fastify/websocket@11.2.0 > ws@8.19.0

**Fix Effort:** Low

## Description

The backend pins `ws` 8.19.0 (pulled by `@fastify/websocket` ^11.2.0) in `backend/package-lock.json`. All `ws` versions from 8.0.0 up to (not including) 8.21.0 are affected by a memory-exhaustion DoS (CVE-2026-48779): a peer can send a high volume of exceptionally small fragments whose structural wrappers consume far more memory than the documented message-size limit, OOM-killing the process. The backend's chat execution WebSocket gateway runs on this version.

## Evidence

**Advisory evidence:** `CVE-2026-48779` applies to `ws` at installed version `8.19.0`. The advisory is fixed in `8.21.0`.

**Transitive dependency:** introduced by the direct dependency `@fastify/websocket@11.2.0`.

**Dependency chain:** `@fastify/websocket@11.2.0 > ws@8.19.0`

**Usage analysis:** the advisory's vulnerable code runs in this codebase. Entry point: Fastify WebSocket upgrade on the backend's execution gateway — `backend/src/websocket/execution.gateway.ts:127` registers `@fastify/websocket` (`import websocket from '@fastify/websocket'` at execution.gateway.ts:16), with routes declared `{ websocket: true }` (execution.gateway.ts:136). Intermediate call: @fastify/websocket@11.2.0 wraps and serves connections through the pinned `ws` 8.19.0 server (backend/package-lock.json:12471). Package call: every WS connection on the gateway is serviced by ws's frame/receiver implementation, the component the advisory's small-fragment memory-exhaustion affects. Peer input is raw network data, controlled by any client that can reach the WS endpoint; fragment size/count is entirely peer-chosen. Chain: ws upgrade request (network) -> @fastify/websocket plugin registration (execution.gateway.ts:127) -> ws 8.19.0 Receiver (vulnerable sink). Note the same vulnerable ws 8.19.0 is also pinned in frontend/package-lock.json:7414 via @supabase/supabase-js realtime and jsdom (test), where it acts as a client — the server-side exposure above is the material one.

## Impact

An unauthenticated network peer that can open a WebSocket connection to the backend can, with modest traffic, drive the Node process into out-of-memory termination — taking down the API/chat-execution service for all tenants.

## Contextual CVSS

Entry point is the WebSocket upgrade handled by @fastify/websocket registered in backend/src/websocket/execution.gateway.ts:127, which dispatches onto the pinned ws 8.19.0 server. Any network peer able to reach the backend's WS endpoint can send the tiny-fragment stream the advisory describes — no authentication is required before the peer starts sending frames (auth is message-level in the gateway), so privileges_required N and user_interaction N. The sink is ws's per-connection fragment accumulation; the demonstrated impact class is memory exhaustion of the Node process hosting the chat execution gateway, i.e. availability H for that service, with no confidentiality or integrity effect.

## Remediation

In backend/package.json, force the resolution of `ws` to >= 8.21.0 (npm `overrides: { "ws": "^8.21.0" }`) or bump `@fastify/websocket` to a release depending on a fixed ws. Verify with `npm ls ws` after the change. The same override should be applied to the frontend lockfile for consistency, though its exposure is client-side only.
