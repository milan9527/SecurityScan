# Unauthenticated avatar generation, presign, and retrieval endpoints (missing authenticate preHandler)

**ID:** vuln-0013
**Severity:** MEDIUM
**Found:** 2026-11-21 10:03:11 UTC
**Target:** /workspace/agentcore-superagent-update/super-agent (backend)
**CWE:** CWE-306
**CVSS:** 6.5
**Confidence:** High
**Fix Effort:** Trivial

## Description

The avatar generation, batch generation, and avatar image-proxy endpoints in avatarRoutes.ts are registered without the authenticate preHandler, allowing unauthenticated users to trigger paid image generation and to fetch any avatar object by key through the backend's S3 proxy.

## Evidence

Source review of routes/avatarRoutes.ts: only the upload route (line 11) and presign route (line 167) include `preHandler: [authenticate]`; the generate (~line 46), generate-batch (~line 101), and `GET /avatars/*` proxy (~line 191) registrations carry no preHandler, and the upload/presign routes in the same file demonstrate the pattern was intended. Local unit PoC backend/tests/unit/avatar-routes.authz.poc.test.ts confirms unauthenticated requests to the generation and retrieval endpoints are processed (no 401), while the authenticated control routes reject missing tokens.

## Impact

Unauthenticated cost/DoS: repeated invocation of the (paid) avatar generation service when enabled, billed to the operator. Unauthenticated reads of avatar images by key (tenant/user avatars are generally low-sensitivity) and unauthenticated presigned-URL minting for arbitrary keys within the avatar service's scope, which can also leak the S3 bucket layout. No demonstrated access to non-avatar data.

## Counterevidence

Checked: POST /avatars/upload (line 11) and GET /avatars/presign/:key (line 167) DO apply `preHandler: [authenticate]` — the omission on generate/generate-batch/proxy is therefore an inconsistency, not an intentional public design. The generate endpoints are gated by the ENABLE_AVATAR_GENERATION env flag (disabled by default), which reduces exposure of the cost-heavy path but is an operator setting, not a control that ships enforced. The proxy endpoint discloses only objects under the avatars/ prefix. No auth, rate limit, or per-key ACL was found on the cited routes.

## Confidence Rationale

Direct source read of all avatar route registrations confirming the absence of the authenticate preHandler (present on other routes in the same file), plus a local unit PoC (avatar-routes.authz.poc.test.ts) confirming unauthenticated 200 responses. Production exposure and cost per request not measured.

## What Would Change This Severity

Measured per-generation cost or confirmation that ENABLE_AVATAR_GENERATION is enabled in production would keep/raise availability impact; evidence that the generation endpoints are disabled everywhere in production would lower this to low.

## Technical Analysis

In routes/avatarRoutes.ts, POST /avatars/upload (line 11) and GET /avatars/presign/:key (line 167) include `{ preHandler: [authenticate] }`, but POST /avatars/generate (~line 46), POST /avatars/generate-batch (~line 101), and the catch-all `GET /avatars/*` proxy do not. The generation handler calls avatarService.generateAvatar(prompt) (an external image-generation call) gated only on the ENABLE_AVATAR_GENERATION env flag, not on any identity. The proxy handler strips leading avatars/ prefixes, re-prefixes the key, and streams avatarService.getAvatarData(key) with Cache-Control: public, max-age=86400. Fastify applies only the preHandlers a route declares, so these routes are anonymous.

## Proof of Concept

1. Send POST /api/avatars/generate with body {"role":"x"} and no Authorization header — the request is processed and generation is attempted (when ENABLE_AVATAR_GENERATION is on). 2. Send POST /api/avatars/generate-batch with {"roles":["a","b",...]} — same. 3. Send GET /api/avatars/<key> unauthenticated — the avatar object is streamed from S3 via the proxy with a public 24h cache header. 4. Control: the same request without a token to /api/avatars/upload or /api/avatars/presign/<key> returns 401, showing those routes do enforce auth.

```gdscript
# Unit PoC: cd super-agent/backend && npx vitest run tests/unit/avatar-routes.authz.poc.test.ts
# No Authorization header on any of these -> processed / 200:
POST /api/avatars/generate          {"role":"x"}
POST /api/avatars/generate-batch    {"roles":["a","b"]}
GET  /api/avatars/presign/<key>
GET  /api/avatars/<key>
# Control: POST /api/avatars/upload without auth -> 401 (that route HAS the preHandler)
```

## Remediation

Add `preHandler: [authenticate]` to the generate, generate-batch, presign, and retrieval routes in avatarRoutes.ts (mirroring the upload route in the same file), and add rate limiting on the generation endpoints. For presign/retrieval, restrict acceptable keys to the `avatars/` prefix and validate the key shape before signing.

## Assumptions

Unauthenticated network access to the API host. The generate/generate-batch endpoints additionally require the operator to have set ENABLE_AVATAR_GENERATION=true (each generation then invokes the external image-generation service, creating per-request cost); the retrieval and presign endpoints are unconditionally open. Production exposure unverified.
