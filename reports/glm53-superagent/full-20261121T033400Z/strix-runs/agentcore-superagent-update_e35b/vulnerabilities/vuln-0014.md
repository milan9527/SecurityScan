# Shell command injection via unvalidated skill name in AgentCore container provisioning

**ID:** vuln-0014
**Severity:** HIGH
**Found:** 2026-11-21 04:09:32 UTC
**Target:** super-agent backend (/workspace/agentcore-superagent-update/super-agent/backend)
**CWE:** CWE-78
**CVSS:** 8.8
**Confidence:** Medium
**Fix Effort:** Low

## Description

In AgentCore runtime mode, skill names are interpolated unsanitized into shell commands executed inside the AgentCore runtime container. `runCommand(sessionId, \`mkdir -p /workspace/.claude/skills/${skill.name}\`)` builds a bash command from a skill name that is fully attacker-controlled (derived from an uploaded zip's directory name or the marketplace install reference), and the command wrapper only escapes single quotes and backslashes — so `;`, `$()`, and backticks pass through to `/bin/bash -c`, giving arbitrary command execution in the runtime container.

## Evidence

Local execution of the exact wrapping logic with a hostile skill name:

```bash
$ node - <<'NODE'
const c = `mkdir -p /workspace/.claude/skills/${'pwn; touch /tmp/fs-poc/shell-injected; #'}`;
const shellEscape = (cmd) => `$'${cmd.replace(/\\/g, '\\\\').replace(/'/g, "\\'")}'`;
const full = `/bin/bash -c ${shellEscape(c)}`;
console.log('EXECUTING:', full);
require('child_process').execFileSync('/bin/bash', ['-c', `exec ${full}`]);
NODE
EXECUTING: /bin/bash -c $'mkdir -p /workspace/.claude/skills/pwn; touch /tmp/fs-poc/shell-injected; #'
```

```text
-rw-r--r-- 1 pentester pentester 0 Nov 21 04:08 /tmp/fs-poc/shell-injected
=== SHELL INJECTION VIA SKILL NAME CONFIRMED ===
```

The `; touch ...` segment executed as a separate command after the intended `mkdir`, proving the wrapper does not contain the injected metacharacters.

## Impact

Arbitrary command execution inside the AgentCore runtime container as the container's user: reading or modifying any workspace file across sessions hosted by that container, exfiltrating container credentials (including the `WORKSPACE_S3_REGION`-configured AWS credentials used by the in-container S3 client), and pivoting to the workspace S3 bucket. Container-level RCE, contained by the AgentCore runtime sandbox boundary.

## Counterevidence

The service does contain a dedicated `sanitizePath` helper (agentcore-command.service.ts:216-222) that blocks `/`, `..`, and shell metacharacters — but it is only invoked in `readFile`, `writeFile`, `deleteFile`, `deleteDirectory`, and `syncFileFromS3`; neither `runCommand` call site applies it. The `shellEscape` helper does correctly neutralize single quotes and backslashes, so injection requires a metacharacter outside those two (trivially available: `;`, `$()`, backticks). No WAF or command allowlist exists between the API route and the SDK call. The main mitigating constraint is configuration reachability: with the default `AGENT_RUNTIME=claude`, these code paths are skipped entirely — impact is limited to agentcore/openclaw deployments.

## Confidence Rationale

The injection mechanism was demonstrated locally by replicating the exact `shellEscape` + `/bin/bash -c` wrapping from agentcore-command.service.ts and executing the forged command in a sandbox shell; the code path from the user-controlled skill name to the `runCommand` call is a complete static trace (upload-zip → DB skill name → marketplace install/enterprise-skill sync with agentcore runtime active). Not executed against a live AgentCore runtime because the isolated local assessment has no AWS runtime; the only unverified step is AWS-side invocation, which is a direct SDK call with the injected string as the command body.

## What Would Change This Severity

Confirmation that a production deployment runs agentcore mode with permissive skill creation would keep this at high; evidence that container commands run as a locked-down user with no credentials and no cross-session access would lower it to medium.

## Technical Analysis

`AgentCoreCommandService.runCommand` (`src/services/agentcore-command.service.ts:51-58`) executes `/bin/bash -c ${this.shellEscape(command)}` inside the AgentCore runtime container. `shellEscape` (:199-202) only escapes backslashes and single quotes, providing no protection against `;`, `&&`, `$()`, or backticks. Two call sites interpolate a skill name directly into that command string:

- `src/routes/skill-marketplace.routes.ts:157-159` — after a marketplace/GitHub skill install into a session, `agentCoreCommandService.runCommand(sessionId, \`mkdir -p /workspace/.claude/skills/${result.name}\`)`.
- `src/services/enterprise-skill.service.ts:338` — `runCommand(sessionId, \`mkdir -p /workspace/.claude/skills/${entry.skill.name}\`)` during enterprise skill sync.

`result.name` / `entry.skill.name` originate from the skill records created by `installFromZip`/`install`, which store the zip directory name or `installRef` segment verbatim (no validation — see the companion path-traversal finding). The service's own `sanitizePath` helper, which blocks `/`, `..`, and `` ` $ ; | & < > ``, is applied only in `readFile`/`writeFile`/`deleteFile`/`deleteDirectory`/`syncFileFromS3` — not on these `runCommand` calls.

## Proof of Concept

1. Replicate the exact command construction: `runCommand` wraps the caller-supplied string as `/bin/bash -c ${shellEscape(command)}` where `shellEscape` only escapes backslashes and single quotes (agentcore-command.service.ts:199-202).
2. Build the command as the marketplace install route does at skill-marketplace.routes.ts:158: `mkdir -p /workspace/.claude/skills/${result.name}` with `result.name` = `pwn; touch /tmp/fs-poc/shell-injected; #` (a legal skill name for the API — derived verbatim from an uploaded zip directory name).
3. Execute the wrapped command through `/bin/bash -c` exactly as the AgentCore container would.
4. Observe the injected `touch` executes as a separate command, creating `/tmp/fs-poc/shell-injected`.

```gdscript
// Exact replication of agentcore-command.service.ts wrapping + hostile skill name
const skillName = 'pwn; touch /tmp/fs-poc/shell-injected; #'; // stored via upload-zip dir name
const command = `mkdir -p /workspace/.claude/skills/${skillName}`; // skill-marketplace.routes.ts:158

// service shellEscape (agentcore-command.service.ts:201)
const shellEscape = (cmd) => `$'${cmd.replace(/\\/g, '\\\\').replace(/'/g, "\\'")}'`;
const full = `/bin/bash -c ${shellEscape(command)}`;
console.log('EXECUTING:', full);

const { execFileSync } = require('child_process');
execFileSync('/bin/bash', ['-c', `exec ${full}`]); // -> /tmp/fs-poc/shell-injected created
```

## Remediation

Route every directory-creating operation through the existing `sanitizePath`/`writeFile` helpers instead of composing raw `mkdir -p` command strings: replace the `runCommand(sessionId, \`mkdir -p /workspace/.claude/skills/${name}\`)` calls at skill-marketplace.routes.ts:158 and enterprise-skill.service.ts:338 with a dedicated `mkdirDirectory` wrapper that applies `sanitizePath` (which already rejects `/`, `..`, and all shell metacharacters) or, better, rejects any name not matching `^[A-Za-z0-9._-]+$`. Enforce the same validation at skill creation so a hostile name can never be persisted. Optionally harden `shellEscape` to full POSIX single-quoting (`'...'` with `'\''` for embedded quotes) so no caller can regress the wrapper.

## Assumptions

Authenticated org member who can install a skill with a crafted name (same prerequisite as the path-traversal finding — the skill name is attacker-controlled). Requires a deployment running `AGENT_RUNTIME=agentcore` or `openclaw`, which is a documented, supported production mode of this platform.
