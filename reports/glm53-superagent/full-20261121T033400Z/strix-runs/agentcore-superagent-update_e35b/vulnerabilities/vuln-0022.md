## Description

axios 1.13.6 is pinned in the production dependency tree (transitive via @larksuiteoapi/node-sdk, @wecom/aibot-node-sdk, and dingtalk-stream) and is covered by numerous 2026 advisories, including prototype-pollution-based HTTP transport hijacking and header injection (CVE-2026-42033/42035), information disclosure and request manipulation (CVE-2026-42264, CVE-2026-44495), NO_PROXY bypass (CVE-2026-42043), proxy-credential leaks on redirects (CVE-2026-44486/44487), and DoS (CVE-2026-44488). Fixed in 1.16.0.

## Evidence

**Advisory evidence:** `CVE-2026-42264` applies to `axios` at installed version `1.13.6`. The advisory is fixed in `1.16.0`.

**Dependency chain:** `@larksuiteoapi/node-sdk@1.60.0 > axios@1.13.6; @wecom/aibot-node-sdk@1.0.6 > axios@1.13.6; dingtalk-stream@2.1.6-beta.1 > axios@1.13.6`

**Usage analysis:** the advisory's vulnerable code runs in this codebase. axios executes on the IM integration path: src/routes/im.routes.ts imports the three SDK-backed adapters (src/services/feishu-adapter.ts, wecom-adapter.ts, dingtalk-adapter.ts), which drive outbound requests through the SDKs' axios instance when IM gateways connect and when messages are sent. Webhook URLs used by the IM flows are operator-configured; full attacker control of axios options was not traced, so exploitation requires attacker influence over request parameters or redirects, hence conservative impact scoring.

## Impact

If any IM adapter passes attacker-influenced values (e.g. webhook URLs, headers from IM event payloads) into SDK HTTP calls, prototype-pollution and redirect-handling flaws could enable request manipulation or credential leakage from outbound IM API calls.

## Contextual CVSS

axios is a transitive dependency of the three IM SDKs (Lark, WeCom, DingTalk), each imported and initialized by the backend's IM gateway services (src/routes/im.routes.ts imports feishu-adapter, wecom-adapter, dingtalk-adapter). The SDKs make outbound requests to the IM platforms; prototype-pollution/hijack CVEs could be triggered via values flowing into SDK request options. However, no direct attacker-controlled URL/header was traced into an axios call within this assessment, so impact is scored conservatively at the level demonstrated by reachability of the library (code executes on the request path), not by a proven exploit.

## Remediation

Force-resolve axios to >= 1.16.0 in package-lock (npm overrides / resolution) and audit the IM SDKs for updated releases; verify with `npm ls axios` after regeneration.

## Assumptions

Version from package-lock.json (offline trivy). Reachability assessed from source imports of the IM SDKs.
