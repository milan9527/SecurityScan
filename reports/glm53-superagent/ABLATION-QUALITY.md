# 独立对照的质量核验

三组性能实验已完成。本文件记录 24 份响应的人工抽查结果；不提供准确率或召回率估计。模型提出的验证方案没有在本轮执行。

## 核验方法

对 baseline、concise、mtp 的四个场景、两种并发各抽取 iteration=0，共 24 份响应。按根因比较，检查源码位置、攻击者前提、验证方案与修复建议；不以发现数量或严重性标签作为准确率。

未标出问题不自动视为漏报，除非源码及调用边界足以支持该问题；新增问题也不自动算改进。对依赖部署方式的风险，检查响应是否明确写出条件。没有完整人工标注集，本轮不报告精确率、召回率或“质量无损”。

## 基线中需要重点复核的结论

| 场景 | 源码与响应中的核验点 | 判定边界 |
|---|---|---|
| 认证授权 | Cognito 模式使用 userPoolId 作为内部 token 的 HMAC 密钥，并接受内部 token 用户字段 | userPoolId 不是秘密；需要保留模式、可达接口等前提，不能只写泛化的 JWT 风险 |
| 认证授权 | 缺少资源 owner 时授权分支放行、默认 owner 角色、组织选择和注册行为 | 必须检查调用者是否传入 owner、后续数据库覆盖及组织策略 |
| 文件路径 | S3 object key 中的 `..` 被描述成文件系统路径穿越 | S3 key 不自动执行文件系统路径规范化，单凭 `..` 不足以证明越权 |
| 文件路径 | `startsWith(workspacePath)` 缺少目录分隔符 | 应使用共享目录名前缀的相邻路径验证；普通 `../s2` 并不必然通过 `/s1` 前缀检查 |
| 文件路径 | Python `zipfile.extractall` 被描述为直接 Zip Slip | 既有 Python 3.9.25 本地验证不支持该说法；需核对实际提取库和版本 |
| 文件路径 | `git clone` 被描述成自动执行远端仓库 Git hooks | 普通克隆不会传递并自动执行远端 `.git/hooks`，不能据此断言代码执行 |
| Webhook/OAuth | 配置保存 webhook secret，但触发路径未验证签名 | 需要明确 webhook ID 泄露或可获知这一前提，并区分随机 ID 与签名认证 |
| Webhook/OAuth | IP allowlist 在缺少 IP 时放行 | 当前 HTTP 路由传入 `request.ip`；不能把缺少参数的内部调用直接当成现有 HTTP 绕过 |
| Webhook/OAuth | OAuth state 重放、过期及组织绑定 | 源码存在随机 state、删除、过期和 provider/组织绑定，不能忽略已有控制 |
| 工具执行 | AgentCore 进程内没有显式认证就被称为公网未授权入口 | 需要核对托管入口 IAM 认证、网络可达性及执行角色权限 |
| 工具执行 | `bypassPermissions`、Bash 工具被直接判为漏洞 | 必须结合用户权限、沙箱边界与产品预期能力 |
| 工具执行 | 同组织成员查看日志、终止任务被称为越权 | 需确认产品组织共享策略及具体权限检查 |
| 工具执行 | MCP 地址访问 IMDS、工作区 filepath 穿越 | 需核验下游协议、IMDSv2、路径解析和边界校验，不把条件性调用直接当成利用成功 |
| 工具执行 | viewer 可以注册任意 MCP server | 创建路由存在 `authenticate, requireModifyAccess`；不能忽略权限中间件 |
| 文件路径 | `walkDir` 上传工作区符号链接指向的文件 | `Dirent.isDirectory()` 不跟随链接，但文件分支的 `statSync` 和读取会跟随文件链接；仍需攻击者能创建链接、目标文件可读等前提 |
| 文件路径 | `git clone ext::...` 直接执行命令 | Git 默认禁用 ext transport，需证明运行环境显式允许；不能仅凭 URL 可控判定 |

## 精简输出组的抽查

已阅读该组四个场景、两种并发的 iteration=0，共 8 份响应。表格通常保留了位置、前提、验证建议和修复建议，但格式完整不能替代事实正确。以下问题在基线中也有部分出现，不能据此判定由精简指令造成。

| 场景 | 抽查结果 |
|---|---|
| 认证授权 | 保留了 public userPoolId 用作 HMAC 密钥的核心问题；部分响应仍将时序差异、角色撤销、跨组织身份迁移的条件性风险写得过强。数据库成员信息覆盖角色的逻辑需要一起分析。 |
| 文件路径 | 保留了不带目录边界的前缀检查和有条件的 S3→本地恢复风险；仍误称 `path.join` 不规范化 `..`，普通相邻路径的验证方案未必命中前缀缺陷。Python Zip Slip、默认 Git ext transport 执行等结论缺少支持。 |
| Webhook/OAuth | 保留了已知 webhook ID 时缺少签名验证的风险；忽略显式缓存失效而声称删除后仍有效、把缺少内部 IP 参数当成 HTTP 绕过、推测随机 256-bit secret 可被破解，均不足以成立。 |
| 工具执行 | 多处明确了网络、组织共享或下游校验前提；但进程内无认证不等于托管入口无 IAM 认证，工具权限不等于沙箱逃逸。S3 key 的 `..`、Git 默认行为和未执行的 shell 验证方案仍存在错误。 |

精简组并没有消除重复根因，也没有证明质量无损。本轮验证方案均未执行，响应中“观察到”“当前返回 200”等措辞不应作为测试证据。

## MTP 组的抽查

已阅读四场景、两种并发的 iteration=0，共 8 份响应。

| 场景 | 抽查结果 |
|---|---|
| 认证授权 | 保留 public userPoolId 用作 HMAC 密钥的问题，认识到参数化 SQL 的已有保护；默认 owner、全局限流和时序攻击等主张仍需部署或版本证据。缺失 owner 的条件性风险并非每份都提及。 |
| 文件路径 | 保留目录前缀缺陷和文件符号链接上传的条件性风险；仍误判 Python Zip Slip、Git 默认 ext transport 和 branch 参数注入。一个修复建议将 relative 的根目录与目标参数写反，不能直接采用。 |
| Webhook/OAuth | 保留未校验签名且需要已知 webhook ID 的核心前提；一份正确认识现有 state 控制和删除缓存失效，另一份仍夸大缺少内部 IP 参数、缓存失效和 state 的风险。PKCE 建议不等于已证明拦截攻击。 |
| 工具执行 | 有些建议注明网络和组织权限前提，但未充分考虑托管 IAM、IMDSv2 协议以及产品允许的工具能力。依然存在 S3 key 路径语义错误、未经执行的“观察到 200”描述及条件性下游 filepath 风险。 |

## 综合判断

三组均保留了一些核心风险，也均有错误、遗漏和不成立的验证建议。样本仅覆盖每个场景/并发首份响应，没有执行其建议的 PoC，没有建立全面真值集，不能声称精简或 MTP 质量无损，也不能把某份基线回答当作真值。需要对拟采用的发现与修复逐项核验。

精简组正文未变短，主要减少思考 tokens；MTP 则明显降低近似 TPOT。完整性能数字见 [测试报告](RESULTS.md)。`finish_reason=stop` 且存在正文只代表请求完成。
