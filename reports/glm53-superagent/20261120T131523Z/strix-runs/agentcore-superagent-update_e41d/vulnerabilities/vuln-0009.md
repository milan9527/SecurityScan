**Fix Effort:** Trivial

## Description

`js-yaml` 4.1.1 is pinned in `super-agent/backend/package-lock.json` and is covered by advisory CVE-2026-53550 (fixed in 4.2.0). The backend parses user-supplied YAML OpenAPI specs with it.

## Evidence

**Advisory evidence:** `CVE-2026-53550` applies to `js-yaml` at installed version `4.1.1`. The advisory is fixed in `4.2.0`.

**Usage analysis:** the advisory's vulnerable code runs in this codebase. super-agent/backend/src/routes/integrations.routes.ts:70 (authenticated route, user `specContent`) -> super-agent/backend/src/services/api-spec-parser.service.ts:8 import `load as yamlLoad` -> api-spec-parser.service.ts:183 `yamlLoad(trimmed)` on the raw user-supplied string. Route enforces `authenticate` (integrations.routes.ts:55) but no schema/content validation precedes the parse.

## Impact

The vulnerable js-yaml parser executes on attacker-controlled YAML supplied by any authenticated user via the integration-upload route, so a flaw in the parser is directly triggerable with a low-privilege account.

## Contextual CVSS

js-yaml is imported once, as `load` from 'js-yaml' in super-agent/backend/src/services/api-spec-parser.service.ts:8, and its only call site is `yamlLoad(trimmed)` at super-agent/backend/src/services/api-spec-parser.service.ts:183, reached via `ApiSpecParserService.parseAndGenerate` from the authenticated route `POST /api/scopes/:scopeId/integrations` (super-agent/backend/src/routes/integrations.routes.ts:70), which passes the user-supplied `specContent` string straight to the parser with only an `authenticate` preHandler. An authenticated user therefore controls the parsed YAML, matching the advisory's attacker-input precondition; impact stays within the backend process (scope U) and requires a low-privilege account.

## Remediation

Bump `js-yaml` to at least 4.2.0 in super-agent/backend (direct dependency in package.json, `^4.1.1`) and regenerate package-lock.json.

## Assumptions

Static analysis of imports and call sites; not dynamically executed. Assumes the advisory applies to js-yaml 4.1.1 as flagged by the offline trivy DB.
