# Missing authentication on avatar generation endpoints (POST /api/avatars/generate, /generate-batch)

**ID:** vuln-0005
**Severity:** MEDIUM
**Found:** 2026-11-20 13:33:35 UTC
**Target:** super-agent/backend (local repository)
**CVSS:** 5.3
**Confidence:** High
**Fix Effort:** Trivial

## Description

POST /api/avatars/generate and POST /api/avatars/generate-batch lack the `authenticate` preHandler used by sibling avatar routes, so anonymous callers can invoke paid Nova Canvas image generation and write objects to the shared avatars S3 bucket when the feature flag is enabled.

## Evidence

Local vitest PoC (super-agent/backend/tests/unit/avatar-routes.authz.poc.test.ts, 6/6 passing) mounted the real avatarRoutes plugin with mocked auth/S3/Bedrock: anonymous POST /api/avatars/generate returned 200 with an avatarKey; anonymous POST /api/avatars/generate-batch returned 10/10 successful avatarKeys; no Authorization header sent on any request.

## Impact

Unauthenticated resource consumption (AWS Bedrock Nova Canvas per-image cost) and unauthenticated writes to the global avatars/ S3 namespace. Data confidentiality is unaffected (generated keys are returned only to the caller); impact is cost abuse plus unauthenticated state change.

## Counterevidence

No auth middleware, ownership check, or rate limit exists on these routes — confirmed by mounting the real plugin. Mitigations found: ENABLE_AVATAR_GENERATION defaults to false (.env.example), batch is capped at 10 items, and generated keys are non-enumerable (Date.now + random suffix). These reduce but do not remove the issue when the feature is enabled.

## Confidence Rationale

Working local vitest PoC exercising the real route registration and real handler code with mocked S3/Bedrock; auth gap is visible in the route registration itself.

## What Would Change This Severity

If the flag is enabled by default in production deployments, severity rises to medium (confirmed cost abuse); a per-user rate limit plus auth would eliminate it.

## Technical Analysis

In `src/routes/avatarRoutes.ts`, `POST /avatars/upload` registers `preHandler: [authenticate]`, but `POST /avatars/generate` (~line 50) and `POST /avatars/generate-batch` (~line 119) register only a JSON schema — no `preHandler`. `src/routes/index.ts` registers `avatarRoutes` with `prefix: '/api'` and no global authentication hook exists in `app.ts` (auth is per-route preHandler only), so these endpoints are reachable anonymously. The handlers call `avatarService.generateAvatar`, which invokes Bedrock Nova Canvas (`amazon.nova-canvas-v1:0`, a paid model) and uploads to S3 under a global `avatars/` namespace with no owner binding. A server-side `ENABLE_AVATAR_GENERATION === 'true'` gate exists, but it only controls the feature, not authentication.

## Proof of Concept

1. Set ENABLE_AVATAR_GENERATION=true. 2. Send POST /api/avatars/generate with body {"role":"engineer"} and no Authorization header. 3. Observe 200 and an avatarKey — an S3 object written anonymously. 4. Repeat with POST /api/avatars/generate-batch with {"roles":[10 roles]} — all succeed anonymously.

```js
// vitest PoC: tests/unit/avatar-routes.authz.poc.test.ts (passes 6/6)
const res = await app.inject({ method: 'POST', url: '/api/avatars/generate', payload: { role: 'engineer' } });
expect(res.statusCode).toBe(200);            // no Authorization header sent
expect(res.json().avatarKey).toMatch(/^avatars\//);
const res2 = await app.inject({ method: 'POST', url: '/api/avatars/generate-batch', payload: { roles: ['a','b','c','d','e','f','g','h','i','j'] } });
expect(res2.statusCode).toBe(200);
expect(res2.json().results.filter(r => r.avatarKey)).toHaveLength(10);
```

## Remediation

Add the `preHandler: [authenticate]` option to the POST /avatars/generate and POST /avatars/generate-batch route registrations in avatarRoutes.ts, matching the /avatars/upload route. Optionally add rate limiting and per-user quota for avatar generation.

## Assumptions

Assumes ENABLE_AVATAR_GENERATION=true in the deployment; otherwise the endpoints return 400 (still unauthenticated, but no cost impact).
