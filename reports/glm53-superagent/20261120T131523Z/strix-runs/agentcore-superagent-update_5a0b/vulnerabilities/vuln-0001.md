# Path traversal in pack-deploy endpoints allows reading files outside the industry-packs tree

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-11-20 13:27:12 UTC
**Target:** super-agent/backend (local repository)
**CWE:** CWE-22
**CVSS:** 4.3
**Confidence:** High
**Fix Effort:** Low

## Description

The `packId` and `scopeDirName` parameters of the pack-deploy endpoints (`GET /api/packs/onboarding/:packId/:scopeDirName`, `POST /api/packs/deploy`) are used directly in filesystem path construction (`join(baseDir, 'industry-pack-' + packId)`, `join(packDir, 'scopes', scopeDirName)`) without any traversal or containment check. An authenticated user can supply traversal sequences (e.g. `a/../../` and `../`-chains) to make the service read files outside the `industry-packs` directory tree and return their contents.

## Evidence

Vitest run against the real service and routes (mocked auth/DB only):

```text
✓ tests/unit/pack-deploy-traversal.poc.test.ts (4 tests) 118ms
  ✓ unauthenticated requests are rejected (authenticate preHandler is enforced)
  ✓ URL-encoded ../ traversal reads onboarding.json outside the industry-packs tree
  ✓ benign in-root control returns null for a nonexistent scope
  ✓ direct service-level call (bypassing routing) also traverses
```

The traversal test asserts `body.data.secret === 'TRAVERSAL-MARKER-9f31ab'`, a value written to a marker file in a temp directory outside `industry-packs/`, proving an out-of-root read.

## Impact

Read-only local file disclosure: an authenticated attacker can read the contents of any file with the fixed names consumed by the service (`onboarding.json`, `scope.json`, `sop.md`, `SKILL.md`, `initial-memories.json`, `workflow-plan.json`, `manifest.json`) located anywhere on the server filesystem reachable by the backend process. No write or execute primitive was demonstrated: the appended filenames are fixed, so arbitrary-name files (e.g. `.env`, `package.json`, SSH keys) cannot be read directly, and all writes go through mocked/DB paths that only copy already-read content.

## Counterevidence

The `authenticate` preHandler is enforced on every pack route (verified by the 401 control test), so this is not unauthenticated. The final file read always appends a fixed filename (`onboarding.json`, `scope.json`, `sop.md`, `SKILL.md`, `manifest.json`, `initial-memories.json`, `workflow-plan.json`), so the attacker cannot read arbitrary filenames such as `package.json`, `.env`, or SSH keys — only files with those fixed names outside the pack tree. JSON parse failures are caught and return null (onboarding path) rather than erroring. No WAF or path sanitization exists on this path (locally verified), but the filename constraint is a real ceiling on impact.

## What Would Change This Severity

Discovery of any code path where the fixed appended filename is attacker-influenced (e.g. an endpoint accepting a filename within a scope directory), or confirmation that sensitive files with the consumed fixed names exist in reachable directories, would raise the severity.

## Technical Analysis

`getOnboardingConfig` in `src/services/pack-deploy.service.ts` builds paths as `join(baseDir, 'industry-pack-' + packId)` and `join(packDir, 'scopes', scopeDirName)` where `baseDir = resolve(process.cwd(), '..', 'industry-packs')`. Node's `join` does not reject `..` segments, and the prefix string `industry-pack-` is neutralized by supplying `packId = 'a/../../'` — the resulting segment `industry-pack-a` is canceled by the following `..`, so `packDir` resolves to the parent of the packs base directory, which exists and therefore passes the `existsSync` guard. `scopeDirName` then completes the escape to any directory, and `onboarding.json` inside it is read and returned. The same unvalidated pattern is used in `deploy()` (scope metadata, agents, skills, SOP, workflow reads). Fastify decodes URL-encoded parameters (`%2F`, `%2E%2E`) before they reach the handler, so encoded traversal survives route matching. Only the `authenticate` preHandler protects these routes — any authenticated user of any organization can call them, with no role or admin restriction.

## Proof of Concept

1. Run the PoC test `npx vitest run tests/unit/pack-deploy-traversal.poc.test.ts` in `super-agent/backend` (test file added in this assessment).
2. The test starts a real Fastify instance registering the genuine `packDeployRoutes` with a mocked `authenticate` that accepts any Bearer token.
3. Create a marker file `onboarding.json` containing `TRAVERSAL-MARKER-9f31ab` in a temp directory outside `industry-packs/`.
4. Issue `GET /api/packs/onboarding/a%2F..%2F..%2F..%2F<relative-escape>%2Fleaked-scope` with any Bearer token: `packId = a/../../` resolves `packDir` above the packs base directory (the `industry-pack-a` segment is canceled by the following `..`), and `scopeDirName` traverses from there to the temp directory.
5. Observe HTTP 200 with the marker file's contents returned in `data`.
6. A control request with a nonexistent in-root pack returns `data: null`, and a request without a Bearer token returns 401.

```js
// tests/unit/pack-deploy-traversal.poc.test.ts (excerpt)
const packId = encodeURIComponent('a/../../');            // packDir -> parent of industry-packs
const scope = encodeURIComponent(scopeEscape);            // ../-chain to temp dir with marker
const res = await app.inject({
  method: 'GET',
  url: `/api/packs/onboarding/${packId}/${scope}`,
  headers: { authorization: 'Bearer anything' },
});
expect(res.statusCode).toBe(200);
expect(JSON.parse(res.body).data.secret).toBe('TRAVERSAL-MARKER-9f31ab');
```

## Remediation

Validate that `packId` and `scopeDirName` match a strict allowlist pattern (e.g. `^[A-Za-z0-9_-]+$`, no slashes or dots) before any path construction. Independently, after resolving the pack and scope directories, canonicalize with `resolve()` and verify the result starts with the canonical packs base directory plus path separator, rejecting otherwise. Apply the same check to the `deploy` flow, which shares the identical join pattern and additionally reads `scope.json`, agents, skills, SOP, and workflow files from the traversed directory.

## Assumptions

Requires any authenticated user of the backend (any role — `authenticate` is the only preHandler; no role or admin check). The backend's working directory must be the `backend/` folder so `getPacksBaseDir()` resolves to the sibling `industry-packs/` directory, which is the documented run layout.
