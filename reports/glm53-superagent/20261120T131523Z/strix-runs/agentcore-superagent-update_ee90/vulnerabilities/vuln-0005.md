# Zip-slip in extractSkillZip python3 -m zipfile fallback

**ID:** vuln-0005
**Severity:** MEDIUM
**Found:** 2026-11-20 13:44:29 UTC
**Target:** /workspace/agentcore-superagent-update (super-agent backend)
**CWE:** CWE-22
**CVSS:** 5.3
**Confidence:** Medium
**Fix Effort:** Low

## Description

The skill-archive extraction fallback `python3 -m zipfile -e` does not sanitize archive member paths, so a skill.zip containing `../` members writes files outside the extraction directory (zip-slip) during workspace provisioning.

## Evidence

Local PoC: crafted zip with member `../../../../../tmp/marker-zipslip.txt` extracted with `python3 -m zipfile -e` into a target dir produced the file outside that dir (marker verified on disk).

## Impact

Arbitrary file write outside the skill directory as the backend process user, when the python3 fallback is used.

## Counterevidence

Primary path uses system unzip, which refuses `../` members (Info-ZIP behavior) and would block the attack; the python3 fallback only runs when unzip is unavailable or errors. The route only accepts .zip/.tar.gz/.tgz extensions (skill-marketplace.routes.ts:272), which does not constrain archive member names.

## Confidence Rationale

zip-slip behavior of python3 -m zipfile confirmed locally with a crafted archive; reachability is conditional on the python fallback branch being taken (unzip missing/failing), which is environment-dependent and could not be verified against a deployed host.

## What Would Change This Severity

Confirmation that the production image lacks `unzip` (forcing the fallback on every extraction) would raise this to high.

## Technical Analysis

extractSkillZip (src/services/workspace-manager.ts:1049-1061) first tries `unzip -o <zip> -d <dir>` and on failure falls back to `python3 -m zipfile -e <zip> <dir>`. Python's zipfile module extracts member names without path sanitization, so archive members containing `../` escape targetDir. The zip originates from S3 (skill.s3Prefix + 'skill.zip'), i.e. from skill uploads (skill-marketplace installFromZip / upload flows), which accept user-supplied archives. Local PoC confirmed the escape.

## Proof of Concept

1. Upload a skill whose skill.zip contains a member named `../../../../../tmp/marker-zipslip.txt` (stored to S3 via the normal skill upload path). 2. Ensure the extraction path takes the python3 fallback (unzip unavailable/failing on the host). 3. Start a session that provisions the skill — extractSkillZip writes the member outside the skill dir.

```python
import zipfile
zipfile.ZipFile('/tmp/wsharness/evil.zip', 'w').write('/etc/hostname', '../../../../../tmp/marker-zipslip.txt')
# then: python3 -m zipfile -e /tmp/wsharness/evil.zip <targetDir>
# locally produced the file outside targetDir (verified).
```

## Remediation

Replace the python3 -m zipfile fallback with a sanitizing extractor (reject members with absolute paths or `..` segments, verify resolved destination stays inside targetDir), or drop the fallback and fail closed when unzip is unavailable.

## Assumptions

Attacker controls the skill.zip content in S3 (normal skill upload path) and the backend host lacks the `unzip` binary (or unzip fails), triggering the python3 fallback.
