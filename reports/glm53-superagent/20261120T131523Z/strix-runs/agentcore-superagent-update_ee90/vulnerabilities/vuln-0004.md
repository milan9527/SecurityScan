# Path traversal via skill/generated-skill names in workspace provisioning (downloadSkill, installSkillToWorkspace, generateAgentSubagentFiles)

**ID:** vuln-0004
**Severity:** MEDIUM
**Found:** 2026-11-20 13:44:16 UTC
**Target:** /workspace/agentcore-superagent-update (super-agent backend)
**CWE:** CWE-22
**CVSS:** 6.5
**Confidence:** High
**Fix Effort:** Low

## Description

Skill names flow unvalidated from authenticated-user-controlled and externally-derived sources into path joins in WorkspaceManager.downloadSkill, installSkillToWorkspace, and generateAgentSubagentFiles (generated skills), allowing arbitrary file write outside the workspace root during session workspace provisioning. A skill or generated-skill name containing ../ makes the backend write attacker-controlled SKILL.md content (skill body) to arbitrary paths as the backend process user.

## Evidence

Local harness replicating downloadSkill's exact logic: join(skillsDir, '../../../../../../tmp/marker-evilskill') → mkdir(recursive) + writeFile produced /tmp/marker-evilskill/SKILL.md outside the workspace (verified via fs.access). The cp(localPath, skillDir) variant produced /tmp/marker-localskill/SKILL.md from a local skill source. PoC3 also confirmed zip extraction: python3 -m zipfile -e extracts '../' zip members outside the target directory (marker /tmp/wsharness/extracttest/tmp/marker-zipslip.txt).

## Impact

Arbitrary file write (content partially attacker-controlled via skill body / generated-skill body) outside the session workspace, as the backend process user. Enables overwriting config, other tenants' workspaces, or any file writable by the backend user.

## Counterevidence

Searched for sanitization of skill.name at every hop: skills.routes.ts:51 POST /api/skills applies no schema/regex to name; skill.service.createSkill stores raw; buildScopeForWorkspace (chat.service.ts:425-460) maps it raw; downloadSkill and generateAgentSubagentFiles contain no containment checks. The one guard that exists (deleteWorkspaceSkill startsWith, workspace-manager.ts:1420) is not on the write path. installFromZip/GitHub paths derive names from external content rather than validating, which broadens rather than restricts.

## Confidence Rationale

Sink code read in full and traversal write of SKILL.md confirmed locally; the DB-side control of skill.name (via /api/skills create with unvalidated name) is a direct straight-line path with no intervening sanitization.

## What Would Change This Severity

Demonstrating that a planted file is auto-executed by the backend or runtime (module resolution, cron) would raise to critical/high-with-RCE; restricting skill creation to tenant-admin roles would lower privileges_required.

## Technical Analysis

downloadSkill (src/services/workspace-manager.ts:968) computes `const skillDir = join(targetDir, skill.name)` with no traversal check, then either `cp(skill.localPath, skillDir, {recursive:true})` (localPath from skill metadata, also unvalidated) or writes SKILL.md with skill.body/description (inline fallback, lines 1020-1046). skill.name originates from POST /api/skills (skills.routes.ts:51 — no schema on name, only authenticate), marketplace install (name derived from external GitHub/skills.sh content: installRef substring or directory/file names from attacker-hosted repos), zip upload (parent directory name inside an attacker-supplied archive), and generated skills from agent model_config.generatedSkills / tools[].name (agents.routes.ts:177 model_config: additionalProperties true). generateAgentSubagentFiles (workspace-manager.ts:738+) similarly joins skillsDir with generated skill.name and writes SKILL.md, and joins agentsDir with agent.name + '.md'. Session provisioning (ensureSessionWorkspace, called from chat.service on every new chat/session) makes this reachable by any user who can start a chat in a scope with the malicious skill bound. Local replication of the exact join+mkdir+write logic confirmed the out-of-root write.

## Proof of Concept

1. Create a skill via POST /api/skills (skills.routes.ts:51 — no name validation) or via marketplace import whose derived name contains `../` segments, with metadata.body set. 2. Bind the skill to a scope and start a chat session. 3. ensureSessionWorkspace → downloadSkill computes join(skillsDir, skill.name) and writes SKILL.md with the attacker-controlled body — confirmed locally that this lands outside the workspace root.

```gdscript
// Replicated sink (exact lines from workspace-manager.ts:968-1029), run locally:
const { join } = require('path');
const { mkdir, writeFile, cp } = require('fs/promises');
const skillsDir = join('/tmp/wsharness/ws', '.claude', 'skills');
const skill = { name: '../../../../../../tmp/marker-evilskill', body: 'pwned-content' };
const skillDir = join(skillsDir, skill.name);           // downloadSkill line 969
await mkdir(skillDir, { recursive: true });             // creates dirs outside workspace
await writeFile(join(skillDir, 'SKILL.md'), skill.body);// marker written outside
// → /tmp/marker-evilskill/SKILL.md confirmed on disk.
```

## Remediation

Apply a single shared containment helper at the write sites: validate skill/subagent/generated-skill names against ^[A-Za-z0-9._-]+$ (no separators, no leading dash) at API ingestion (skills.routes.ts create/patch, skill-marketplace install/installFromZip, agents model_config.generatedSkills and tools[].name) and re-check in downloadSkill, installSkillToWorkspace, and generateAgentSubagentFiles that the resolved path stays inside the target directory (reuse the startsWith/relative pattern already present in deleteWorkspaceSkill). Same for agent.name in the .claude/agents/{name}.md join.

## Assumptions

Authenticated org member (skills POST routes require only `authenticate`). Skill names generated from external GitHub content (skills.sh / probe-github) must be treated as untrusted input.
