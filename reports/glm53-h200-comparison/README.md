状态：2026-11-22 10:55:51 UTC 测试完成，退出码 0。模型身份及真实工具调用往返验证通过；24 个正式请求均正常完成，无错误或截断。

## 测试结论

在本轮配置下，H200 并发 1 / 2 的聚合输出吞吐为 203.9 / 342.0 tokens/s，比 B200 分别低 22.5% / 23.6%；平均 E2E 为 13.740 / 15.407 秒，分别长 34.4% / 38.7%。估算 TPOT 分别长 32.1% / 30.2%。这些结果支持本轮 B200 配置的生成速度更快，但不代表两种 GPU 的最佳性能或同网络条件下的硬件性能差距。

H200 的 TTFT 更短，但首次可见正文更晚；TTFT 包含思考增量，不能用它代替用户等待正文的时间。两侧客户端网络路径和输出长度不同，具体限制见下文。

## 测试范围和口径

先验证模型身份及一次真实工具调用往返，再使用已有 auth、path、webhook、tools 四组离线源代码审计样例。每组预热一次，然后分别以并发 1、2 各重复三次，每种并发 12 个计入统计的请求。温度 0、reasoning effort=low、输出上限 8192 tokens，与 B200 对照使用相同提示词。

本轮是独立流式推理与工具调用验证，不能替代完整 Strix 扫描，也不能将推理吞吐直接解释为漏洞检测能力。

“正常正文完成”仅表示正文非空、以 stop 结束且没有请求错误，不表示发现已通过安全审计或漏洞复现验证。工具调用验证完成 add(19, 23) 往返，最终回答为 42。

B200 数据来自 2026-11-21 的 8×B200 MTP 测试。聚合输出吞吐为整个 8 卡服务在批次墙钟时间内的输出 token 总量，包括模型返回的 reasoning token 计数，并非单卡吞吐。估算 TPOT = (最后生成增量到达耗时 − TTFT)/(输出 tokens − 1)；流式分块可能包含多个 token，因此它不是逐 token 的直接测量。

TTFT 从请求发出计至首个生成内容分块（包括 reasoning/tool calls）；E2E 从请求发出计至完整响应流结束。B200 测试客户端经过 SSM 隧道，H200 客户端位于实例本机，这会影响延迟比较，尤其是 TTFT。每种并发只有 12 个样本，p95 仅供本轮比较。

运行日志提示缺少当前 Triton 3.8.0 的 H200 MoE 调优配置，回退使用 3.5.1 配置，可能影响性能。因此这里比较的是本轮部署配置，不代表两种 GPU 的最佳性能。相同提示词也不保证生成 token 数相同，应结合 TPOT 和输出长度解读 E2E。
