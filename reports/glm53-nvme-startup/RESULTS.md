# GLM-5.3：EBS → 本地 NVMe 启动实验

2026-11-21 UTC，Mumbai `p6-b200.48xlarge` Spot，8×B200。

## 结论

已部署开机自动复制权重到 NVMe，并从 NVMe 启动模型的 systemd 服务。
本次从首次复制到真实推理验证完成约 **9 分 50 秒**；
此前直接从 EBS 加载 **16 分 44 秒仍未就绪**，随后被中断。
本次结果支持使用 NVMe 改善启动，但不是严格冷启动 A/B，不能据此计算准确加速倍数。

EBS 保留权重原件；本地 NVMe 在实例 stop/start 后丢失，必须重新复制。
现有 NVMe 文件系统直接复用，未格式化。尚未通过另一次 EC2 stop/start 验证整个开机流程。

## 真实推理验证

GPU 主机 loopback SSE 请求，`max_tokens=512`、temperature 0、低 reasoning，
保留原模型参数和 MTP 设置。3/3 成功，均返回非空答案、`finish_reason=stop` 及结束事件。

| 请求 | TTFT（秒） | E2E（秒） | 输出 token |
| --- | ---: | ---: | ---: |
| 输出 NVMe ready | 15.865 | 15.866 | 5 |
| 三项授权 API 安全审查检查 | 0.212 | 0.598 | 136 |
| 两句话解释参数化 SQL | 0.066 | 0.324 | 70 |

TTFT 为首个内容 token 到达时间，E2E 为请求发出至完整响应流结束的耗时。SSE 分块会影响观测粒度。首请求仍包含约 15.9 秒尾部预热。
这三个短请求仅验证推理可用，不代表完整 Strix 扫描性能、长上下文吞吐或延迟分位数。
没有证据表明 NVMe 改善权重已驻留 GPU 后的稳态 E2E。
